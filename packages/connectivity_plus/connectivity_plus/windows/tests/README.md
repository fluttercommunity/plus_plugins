# Windows COM cleanup regression

This standalone CTest compiles the actual plugin and `NetworkManager` with the
Flutter Windows wrapper. It exercises the real COM apartment and network
listener without launching a Flutter app. It does not change production builds
or require an additional test framework.

Use an existing Flutter Windows project's `windows/flutter/ephemeral` directory,
generated by a Windows build, for the headers, wrapper sources, and engine DLL.
From the `connectivity_plus` package directory on Windows:

```powershell
$engine = "<flutter-project>/windows/flutter/ephemeral"
cmake -S windows/tests -B build/windows-cleanup-test -A x64 `
  "-DFLUTTER_ENGINE_DIR=$engine" `
  "-DFLUTTER_WRAPPER_DIR=$engine/cpp_client_wrapper"
cmake --build build/windows-cleanup-test --config Release
ctest --test-dir build/windows-cleanup-test -C Release --output-on-failure
```

The caller first initializes its own COM apartment. The plugin and the event
stream then share a manager. After the plugin is destroyed, the listener must
already be stopped but the manager must still be usable. Releasing the stream's
owner must preserve the caller's apartment (`S_OK`).

With the original plugin destructor calling `Cleanup()`, this test fails with
`listener_stopped=false caller_apartment_hresult=0x800401f0`
(`CO_E_NOTINITIALIZED`): the plugin and the manager each call `CoUninitialize()`
for a single manager initialization. With `StopListen()` in the plugin
destructor, it passes with `listener_stopped=true caller_apartment_hresult=0x0`.
A COM initialization or listener setup failure is a test failure, not a pass.
